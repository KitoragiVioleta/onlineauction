# Контракт консольної демонстрації

## Запуск

Точка входу — `onlineauction.Main`. Програма не читає stdin, не приймає
параметрів і завершується з кодом `0` після виконання всіх демонстраційних
сценаріїв.

```text
javac --release 17 -d build (Get-ChildItem -Recurse src -Filter *.java).FullName
java -cp build onlineauction.Main
```

Для Linux/macOS bash:

```bash
rm -rf build
mkdir -p build
javac --release 17 -d build $(find src -name '*.java')
java -cp build onlineauction.Main
```

## Обов'язкові результати stdout

Точний текст може містити ідентифікатори й суми, але запуск має однозначно
показати українські повідомлення про:

- створення лоту та перехід `Чернетка -> На модерації`;
- схвалення і перехід `На модерації -> Активні торги`;
- прийняту допустиму ставку;
- відхилену ставку через час або мінімальний крок;
- завершення з переможцем, підсумкову ціну та симульовану оплату;
- відхилення лоту, пояснення продавцю та повторне подання;
- зняття лоту з дозволеного стану;
- неможливість зняття активного лоту;
- завершення активного аукціону без ставок.

Кожен зі станів `Чернетка`, `На модерації`, `Відхилено`, `Активні торги`,
`Завершено з переможцем`, `Завершено без переможця` і `Знято` має бути
підтверджений повідомленням або перевіркою сценарію.

## Поведінкові гарантії

- Один запуск детермінований і не залежить від системного часу.
- Відхилена ставка не змінює кількість прийнятих ставок.
- Несумісний перехід не змінює стан аукціону.
- Для першої ставки мінімумом є стартова ціна; для наступних — поточна
  найвища ставка плюс мінімальний крок.
- Межі часу включні: `startTime ≤ submittedAt ≤ endTime`.
- Перевірка ставки виконується в порядку стан, час, сума; повідомлення про
  відмову називає операцію, поточний стан і першу порушену умову.
- Рівні ставки розв'язуються на користь ранішого `submittedAt`, а за рівного
  часу — ранішої ставки за порядком додавання.
- Кінцеві стани незворотні, відновлення після них не передбачено.
- Симульована оплата не виконує мережевих або фінансових операцій.

## Матриця повідомлень про відмову

Кожне повідомлення про відмову MUST містити українською мовою назву
операції, поточний стан аукціону та першу порушену умову. Мінімальний набір
перевірок stdout:

| Операція | Приклад першої причини |
|---|---|
| Подання ставки | аукціон неактивний; ставка поза часовими межами; сума нижча за мінімально допустиму |
| Схвалення | поточний стан не `На модерації` |
| Відхилення | поточний стан не `На модерації` |
| Повторне подання | поточний стан не `Відхилено` |
| Зняття | поточний стан не дозволяє зняття, зокрема активні або кінцеві торги |

Повідомлення про успішні операції та результати MUST містити українську назву
операції або результату, достатню для перевірки сценарію без перегляду коду.
